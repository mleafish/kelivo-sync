# 实时同步

多台设备通过一台自建服务器保持数据一致。服务端部署见 `server/README.md`，这里讲客户端怎么配、同步到底做了什么。

## 客户端怎么配

在「设置 → 备份 → 自动同步」里填两样东西：

- **服务器地址**：`https://sync.example.com`，或者 `http://192.168.1.10:8787` 这种直连
- **登录密码**：服务器 `config.json` 里那个

点「连接」。地址会被记住，**密码不会被保存到任何地方**——登录换回来的令牌才是留着的东西，它放在一个标记为"设备本地"的键里，永远不会跟备份或同步跑到别的设备上去。

不需要填端口、用户名、密钥，也不用配同步哪些内容。

## 它是怎么保证"两边一样"的

关键在**服务端是唯一权威**。所有写入先送到服务端，由它排序、发一个递增的版本号，客户端收到后以服务端为准写回本地。两端没有各自为政的机会。

消息的合并方式值得单独说：消息写进去之后就不再变（编辑是**追加一个新版本**，不是改原行）。所以两台设备分别发消息，是两个不相交的集合求并集——**不存在冲突，也就不可能丢消息**。

只有同一个 id 在两端被同时改动时，才需要裁决。规则是"时间戳新的赢，时间戳相同时设备号大的赢"。用设备号兜底是为了让**两端算出同一个结果**：如果规则只是"谁先到服务端谁赢"，两边就会各自以为自己是对的。

## 实时到什么程度

不是靠把轮询调快，而是**服务端主动推**：

- 本端改完，1.5 秒内被发现并推送到服务端
- 服务端立刻通过 WebSocket 通知其它在线的设备
- 对端收到通知就去拉取

所以端到端通常在 2 秒左右。iOS 在后台时系统会挂起定时器，回到前台立即补一次。

## 同步哪些数据

- **聊天**：会话、消息、消息分段、工具调用产物、附件索引、发送给模型的 prompt
- **配置**：助手、服务商、MCP、世界书、快捷短语、指令注入、记忆、标签、TTS/搜索服务、偏好设置
- **删除**：删除会话会同步，用 `tombstone_rows` 传播
- **附件内容**：按内容哈希传输，同一张图两张设备只存一份

**不同步的**是描述"这台设备自己"的东西：

| 不同步 | 原因 |
|---|---|
| 数据库身份、迁移回执 | 每台设备各自的数据库 |
| 正在进行的生成任务 | 运行状态，复制过去没有意义 |
| 资产 GC 队列、审计日志、引用重算队列 | 各自待办的本地工作 |
| 窗口尺寸/位置、桌面快捷键、日志开关 | 设备形态不同 |
| 沙箱环境状态、环境变量、定时任务 | 每台设备各自的环境 |
| 外部挂载授权 | 授权不能在设备间传递 |
| 同步令牌、游标、设备 id | 各自的身份与进度 |

## 冲突时会发生什么

同一会话在两端都改了：

- 时间戳较新的那次修改保留
- 较旧的那次**会被覆盖**

推送之前本端会先把自己的状态发到服务端，所以被覆盖的那份至少还存在于该设备已发布的记录里，不会凭空消失。但如果你在两台设备上同时编辑同一段对话，仍然可能丢一边——这是 last-writer-wins 的固有代价，不是实现缺陷。

## 服务器连不上会怎样

本地读写完全不受影响，照常用。同步会在后台重试（退避到最多 1 分钟一次）。服务器恢复后自动追上。

令牌过期或服务器上改了密码时，客户端会提示需要重新登录。
